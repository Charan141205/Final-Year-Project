The two-window rule particularly reduces isolated `ironing` and `sweep` false-positive windows, but some multi-window false alarms remain.

Interpretation:
  - Requiring >=2 consecutive positive windows reduces validation false-positive windows from
    344 to 63 and reduces false-positive rate from 2.45% to 0.45%.
  - It also reduces true-positive windows from 424 to 389 and fall recall from 65.53% to 60.12%.
  - Fall precision rises from 55.21% to 86.06%; validation F2 moves from 63.17% to 63.98%.
  - Requiring >=3 positive windows reduces false alarms further but causes a larger recall loss
    and a lower F2 (59.41%).
  - Two consecutive windows is therefore a promising offline confirmation candidate, not a
    proven live emergency rule.

Critical caveats:
  - CAPPIMU windows are activity/window-level labels, not exact fall-onset labels.
  - The simulated filter retrospectively marks all windows in a positive run once the run
    reaches the required length. In real-time, confirmation occurs only after the second
    positive window; the first window cannot be confirmed in advance.
  - CAPPIMU sampling timestamps are irregular; nominal 50 Hz / about 1-second windows are
    approximations.
  - Do not infer real emergency detection latency or field false-alarm rates from this analysis.
  - No model, feature order, trained parameters, or classifier threshold has been changed.

Recommendation:
  Keep the classifier frozen. Carry "2 consecutive positive windows" forward as a candidate
  temporal confirmation policy for further offline Python testing. Do not claim it as final
  or deploy it on the physical prototype without event-level ground truth and hardware tests.
